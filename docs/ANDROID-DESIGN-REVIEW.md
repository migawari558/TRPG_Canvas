# Android版デザインレビュー

2026年11月11日。対象ブランチは `codex/android-design-review`。

PC版で採用した原稿と製本の方向を、スマートフォンでの閲覧・短時間の編集へ適用するためのレビュー。
レビュー手法は unslop by Damir Sokolovsky (@heydamir)、CC BY 4.0。

## 確認範囲

- 現在のAndroid用フロントエンドをモバイルモードでビルドし、Electronのスマホ幅で本文・一覧・目次・メモ・設定・フローを確認した。
- 主な測定時の表示領域は414×821 CSS px。明るいモノクロ、フォレスト、暗いミッドナイトを確認した。
- `npm run test:mobile` は成功した。下書き保存、書式操作、ドロワー、キーボード相当の短い表示領域、スクロール時の本文位置を検証している。
- 接続されたAndroid実機・エミュレーターはなかった。Androidのソフトキーボード、戻る操作、システムバー、Driveファイル選択画面は実機検証が必要。

## 優先して改善したい点

| 優先度 | 対象 | 確認した状態 | 改修方針 |
| --- | --- | --- | --- |
| 高 | ダークテーマの一覧 | 「Drive・端末から開く」が明るい固定背景 `#f0f3ec` と明るい文字 `#e0e9ef` の組み合わせになり、コントラストは約1.10。主要操作の文字がほぼ読めない | 背景・文字・枠をテーマ変数へ統一し、主要操作の前景色を背景と組で指定する |
| 高 | タップ領域 | 下部書式ボタンが約34×36px、目次行が約34px。目次・メモのフロートボタンは約42px | アイコンの見た目は16〜18px、タップ領域は最低44pxを設計目標とする。密度は操作数を減らして確保する |
| 高 | 読書中の操作と本文の重なり | 上部が隠れると目次・メモの丸いボタンだけ残る。スクロール中の見出しがその直下を通り、画像では見出しの一部を覆っている | 読書中は小さな共通ツール領域としてまとめる。スクロール領域の高さを途中で変えずに、見出しへの移動先と操作領域の重なりを避ける |
| 中 | タイトル・保存情報 | ヘッダーと原稿に同じタイトルが出る。初回保存時は保存先の案内も常時表示され、原稿のタイトルは画面上端から約145pxの位置にある | ヘッダーは戻る・短い文書名・保存操作に限定する。原稿タイトルは1か所で編集。通常の保存状態は短い表記へ集約し、初回保存や同期エラーの詳細を必要時に表示する |
| 中 | 下部ツールバー | 19操作のうち、通常幅で見えるのは約12操作。横スクロールの先に画像・セリフ・元に戻すなどがある | よく使う操作と挿入操作を分ける。書式・見出し・挿入のグループを短いメニューに整理し、既存の機能をすべて到達可能にする |
| 中 | 表示設定・保存案内 | 保存先や同期の説明が一覧と設定に分散する。10〜12pxの説明と状態表示が多い | 通常表示は短い状態名、詳しい説明は保存設定へまとめる。端末への保存と元ファイルへの反映は別々の状態として示す |
| 中 | フロー | SVG生成が `flowSvg(..., 'mono')` に固定されている。暗い画面に明るい図が入り、図全体が横に切れる | 選択テーマを図へ反映し、初期表示で全体を把握できる縮尺を用意する。拡大や横移動の操作方法も明確にする |
| 低 | 装飾と一貫性 | 戻る・保存・目次・メモがすべて丸い影付きボタン。目次とメモで閉じる位置・見出しとの距離が異なる。本文には追跡幅の広い英文ラベルが残る | フロート要素は読書中の必要な操作に絞る。パネルの見出しと閉じる操作を同じ行へ揃え、原稿内の装飾ラベルを整理する |

## 維持したい点

- 原稿が画面幅を使い、下部で書式を操作できる構成。
- スクロール中も目次・メモを開けること。
- 目次の階層・一括展開、メモの独立編集。
- フローが閲覧専用であることを明示していること。
- 自動保存先が端末か元ファイルかを区別する情報。
- 上部UIを収納しても原稿の高さ・スクロール位置を変えない実装。

## 改修の方向

1. **用途** — 移動中にもTRPGシナリオを読み、本文とメモを編集する道具。
2. **印象** — 静か、読みやすい、確実。
3. **素材の軸** — 手元で開くシナリオ冊子。背景は低彩度、テーマの色は見出しと選択状態へ限定する。
4. **見せ場** — 読みやすい原稿と、迷わずたどれる目次。生成画像より、実際のシナリオ内容の組版に力を使う。
5. **共通の細部** — PC版と同じ細い背表紙の線を、下書き一覧と選択中の目次へ使う。

最初の改修単位は配色とタップ領域、その次が共通ヘッダーと保存情報、最後に書式メニューとフローの縮尺とする。
書式メニューの構成変更とフローの操作追加は、見た目の調整に加えて操作検証が必要。

## 実装時の確認項目

- 360px・412px前後の幅、横向き、本文サイズ10〜24px。
- 全標準テーマとカスタムテーマ。主要ボタンは文字と背景のコントラスト4.5以上を設計目標とする。
- 本文・メモでAndroidのキーボードを開いたときの書式操作とカーソル位置。
- ゆっくり／速いスクロール、方向転換、見出しジャンプ、目次・メモの開閉。
- システムの戻る操作、画面端、システムバーとの干渉。
- 端末保存、元ファイル保存待ち、同期中、同期失敗、初回保存の表示。
- Driveからの読込、開き直し、外部変更との競合、下書き削除の確認。

## このブランチでの改修結果

- 一覧・設定の固定色をテーマ変数へ統一。主要ボタンは全6テーマでコントラスト4.5以上をテストした。
- 本文の書式操作を「書式」「挿入」へ整理し、19操作を保持。書式ボタン・目次行・閉じる操作を44pxにした。
- 編集するタイトルを共通ヘッダー1か所へ集約。端末保存とファイル保存の状態を短く表示し、保存詳細パネルを追加した。
- 読書中も本文／フロー・目次・メモの共通バーを残し、本文をバーの下でクリップする。スクロール前後で本文の高さ・座標が跳ねないことを検証した。
- 目次とメモの見出し・閉じる位置を統一。フローは選択テーマに対応し、全体表示・拡大縮小・空状態を追加した。
- モバイル画面テスト、リンクファイルの自動同期テスト、PC版の起動・保存・書き出しテストが成功した。
- 360px幅のメニュー、本文サイズ24px、メニュー外タップでの閉じる操作をプレビューで確認した。
- Android実機のソフトキーボードとシステムの戻る操作は未検証。
