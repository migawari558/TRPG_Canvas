# Android試作版（codex/android-editorブランチ）

本文のライブMarkdown編集を中心にしたAndroid版です。上部左の丸いボタンから目次、右から執筆メモが開きます。上部中央で本文／フローを切り替えます。フローのカードは閲覧専用です。修飾バーはキーボード直上に配置します。

## PCで画面を試す

```powershell
npm ci
npm run dev:mobile
```

ブラウザで http://127.0.0.1:5173 を開き、開発者ツールのデバイス表示をPixelなどの幅にします。本文、目次、メモ、ファイル取込を試せます。ブラウザのファイル保存はダウンロードです。Androidのファイル選択と元ファイルへの書き込みはエミュレーター／実機で確認してください。

## Android Studioのエミュレーターで動かす

1. Android Studio、Android SDK Platform 35、SDK Build Tools、Android Emulatorをインストールします。Gradle JDKはJava 21を選びます（Android Studio付属のJDKでもバージョンを確認してください）。
2. リポジトリのルートで `npm ci` → `npm run android:sync` を実行します。
3. Android Studioでこのリポジトリの `android` フォルダを開き、Gradle Syncを待ちます。`npm run android:open` でも開けます。
4. Device ManagerでPixelなどの仮想端末を作り、`app` をRunします。
5. ソース変更後は `npm run android:sync` を実行し、Android Studioで再度Runします。

## PCと同じGoogle Driveファイルを編集する

- Android端末またはエミュレーターへGoogle Driveアプリをインストールし、PCと同じアカウントへログインします。エミュレーターはGoogle Play付きのイメージを使います。
- 一覧の「Drive・端末から開く」を押し、Androidのファイル選択画面のメニューからDriveを選択して、PCで使っている `.trpg.json` を開きます。Drive側が書き込みを提供するファイルを選んでください。
- 編集内容は端末内のIndexedDBへ自動保存します。**連携済みの元ファイルへは入力停止後に自動保存します。** 新規シナリオは右上の保存ボタンから初回だけ保存先を選択します。その後は入力停止から約650ms後に自動保存します。元ファイルの最新版はシナリオを開き直した時に読み込みます。
- 通信や権限で保存に失敗した場合、端末の下書きは残ります。元ファイルが別の端末で変わっていたら、上書きを拒否します。PCとスマホで同時編集せず、Driveの同期完了後に切り替えてください。検出はDriveプロバイダーから読めた内容の比較であり、クラウド上の原子的な同時編集制御ではありません。
- アプリ内でシナリオを開き直す際、端末の下書きがある場合はどちらを開くか確認します。下書きのみにある変更を破棄する前に保存してください。
- プロバイダーの保存処理はクラウドのアップロード完了まで保証しません。Driveアプリ側でも同期状態を確認してください。
- ブラウザのデータ消去やアプリのアンインストールで端末の下書きは消えます。必要なシナリオはファイルへ保存してください。

Google Drive専用のOAuth認証／自動同期ではなく、Android標準のStorage Access Frameworkを使う試作です。Drive提供機能の実機検証は別途必要です。PC版のファイル形式とフローのデータは保持します。

## GitHubからスマホへ試作APKを入れる

1. GitHubへログインし、リポジトリのActionsで「Build Android preview」の成功した実行を開きます。
2. Artifactsの `TRPG-Canvas-Android-preview` をダウンロードしてZIPを展開します。中の `app-debug.apk` が試作用アプリです。
3. AndroidでAPKを開き、ブラウザ／ファイルアプリからの「不明なアプリのインストール」を必要に応じて許可し、インストールします。

Actionsの成果物は保存期限があります。これは正式公開リリースではなく開発用デバッグ版です。CIの実行ごとに署名鍵が変わるため、前の試作版へ上書きインストールできない場合があります。その場合、必要な下書きを元ファイルへ保存してから旧試作版をアンインストールしてください。PC版とは別アプリです。

## 検証

本文の標準は14pxです。旧試作版の10px設定はこの更新の初回に14pxへ移行し、その後変更したサイズは保存します。ホームの下書きを左へスワイプすると削除確認が開きます。削除するのは端末の下書きだけです。

元ファイルへの保存は書き込み後の再読込で一致を確認します。これはDriveクラウドへのアップロード完了を保証しません。PCに反映されるまで時間がかかることがあります。Androidから新しく作るファイル名はPC互換の `シナリオID.trpg.json` です。タイトル名の旧試作ファイルは保存時にID名へ変更します。

## 正式Android版のアプリ内更新

設定の「更新を確認」は `android-vX.Y.Z` タグで公開済みのAndroidリリースとAPKを探します。PC版リリースや未公開の下書き、プレリリースは対象外です。更新があれば配布ページを開き、APKをダウンロードして上書きインストールします。無操作でのインストールは行いません。

正式リリース用のワークフローは `.github/workflows/android-release.yml` です。公開前に管理者が長期保管する署名鍵を用意し、GitHub Actions secretsへ `ANDROID_KEYSTORE_BASE64`、`ANDROID_STORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD` を設定してください。同じ鍵を全更新に使います。タグpushで署名APK付きの下書きリリースを作ります。確認後に公開するとアプリ側から検出できます。署名鍵の未設定時はリリースビルドを停止します。現在は正式版を公開していません。

デバッグ試作版と正式版は鍵が違うため、正式版へ移る際はファイルへ保存してから試作版を削除してください。

`npm run test:mobile` でスマホ幅の本文編集、左右パネル、フローの閲覧専用、修飾バー位置、下書きの再読込を確認できます。これはElectronでWeb画面を検証するテストであり、AndroidのIME・ソフトキーボード・Drive書き込みの実機検証とは別です。

## 自動保存・開き直し・競合（PC版と同じ流れ）

- 元ファイルに紐づく下書きは、本文・メモ・シナリオ情報の入力停止から約650ms後に自動保存します。初回の保存先選択は右上から行います。
- 編集中の定期的な取込や、画面復帰だけでの本文差し替えは行いません。PC側の変更を読み込むには、シナリオを一覧に戻して開き直してください。
- 保存時は読込時／前回保存時のハッシュと現在の元ファイルを比較します。異なれば元ファイルは上書きせず、PC版と共有した処理でスマホの編集を別IDの「競合コピー」として端末に保護し、そのコピーで編集を続けます。元ファイルの内容が読めない場合も編集のコピーを保護します。
- 単一ファイルのアクセス権では同じDriveフォルダに新しいファイルを自動作成できないため、競合コピーは端末内に残ります。コピーをDriveへ置くには、初回の保存先を選んでください。
- オフライン時は端末の下書きを保護し、未保存分だけを再試行します。保存先を再選択せずに権限が復旧すれば保存できます。読み込み時に通信できない場合は、その旨を表示して端末の下書きを開きます。
- 未保存の編集が残った状態で元ファイルを開き直す場合、まず保存時の競合チェックで編集を保護してから開きます。
- Androidが終了・停止している間の常駐保存はありません。Driveのクラウド反映には時間差があり、PCとスマホの同時編集を原子的にロックする仕組みではありません。

`npm run test:mobile-sync` は模擬Android文書プロバイダーと実際のスマホUIを使い、保存ボタンなしの送信・編集中は外部変更を取り込まないこと・開き直しでの更新・競合コピーでの編集継続を検証します。
